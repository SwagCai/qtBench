# Tamari Trivariate Hilbert-Series-Shadow Third Statistic

## Task

Find a statistic `statistic(pair)` on pairs `(f, alpha)` of a parking function
and a Tamari-smaller Dyck path such that the joint distribution

```text
sum_{(f, alpha)} q1^chain(f, alpha) q2^dinv(f) q3^statistic(f, alpha)
```

matches qtBench's unrefined target polynomial `H_n(q1, q2, q3)` for every
tested size `n`.

This `t_statistic_discovery` task is the only one with **two** public statistics:
the Tamari chain length
`chain(f, alpha) = d(alpha, beta(f))` and the parking function `dinv(f)` -- so
its target is graded by three variables instead of two. This arity is data, not
a task type. It is the length of `known_statistics` in `metadata.json`, and the
problem remains in the ordinary `t_statistic_discovery` folder.

The target is the trigraded Hilbert-series shadow of the space `Harm_n` of
**trivariate diagonal harmonics** of Bergeron and Preville-Ratelle,

```text
H_n(q1, q2, q3) = sum_{d in N^3} dim(Harm_{n,d}) q1^{d1} q2^{d2} q3^{d3},
```

where `Harm_n` is the space of polynomials in three sets of `n` variables killed
by every polarized power sum. Their Equation (49) asks for a statistic
`nu(f, alpha)` completing their conjecture to a full combinatorial description,

```text
Frob(Harm_n)(w; q1, q2, q3)
  = sum_{beta} sum_{f in Park(beta)} sum_{alpha <= beta}
        q1^{d(alpha,beta)} q2^{dinv(f)} q3^{nu(f,alpha)} Q_{co(f)}(w),
```

and the unrefined scalar target above is what that identity becomes once every `S_n`
representation is replaced by its dimension: on the left each `s_lambda(w)` of
`Frob(Harm_n)` becomes the number `f^lambda` of standard Young tableaux of shape
`lambda`, and on the right each `Q_{co(f)}(w)` becomes `1`, leaving exactly one
monomial per pair `(f, alpha)`. The paper writes "such a statistic still has to
be found, even in the case `r = 1`", which is the case published here.

**Scope of the executable challenge.** This specialization forgets the
fundamental-quasisymmetric factor `Q_{co(f)}(w)`. The checker therefore does not
retain the `co(f)` refinement and cannot certify Equation (49) itself: values may
be reassigned between different `co(f)` classes while preserving every scored
coefficient. Problem `12` is consequently a weaker qtBench-derived scalar
challenge. Passing it must not be reported as solving the cited Frobenius problem.

Two specializations are pinned down and are exactly the checks the public data is
built to satisfy:

- in the full source conjecture, at `q3 = 0` only the pairs with `nu = 0` survive, and the identity becomes the
  **shuffle theorem** `H_n(q1, q2, 0) = sum_f q1^{area(beta(f))} q2^{dinv(f)}`
  (a theorem of Carlsson and Mellit). The paper expects `nu(f, alpha) = 0` exactly
  when `alpha` is the Tamari minimum; this pointwise zero locus is not part of
  the weaker executable scalar contract;
- at `q3 = 1` the identity becomes their Conjecture 1,
  `H_n(q1, q2, 1) = sum_{(f, alpha)} q1^{chain(f, alpha)} q2^{dinv(f)}`, which is
  computable directly from the objects and the two public statistics.

For the published cases `1 <= n <= 5`, `H_n` is symmetric in `q1, q2, q3` and
totals `2^n (n+1)^{n-2}`, the number of public objects. The source reports these
trigraded Frobenius characteristics through `n = 5`; the assertion
`dim Harm_n = 2^n (n+1)^{n-2}` for all `n` is Haiman's conjecture, not a theorem.

## Objects

A **Dyck path** of height `n` is the weakly increasing vector
`alpha = (a_1, ..., a_n)` with `0 <= a_i <= i - 1`, where `a_i` counts the cells
to the left of the path at height `i`. A **parking function** of length `n` is a
sequence `f = (f_1, ..., f_n)` of nonnegative integers whose weakly increasing
rearrangement `beta(f)` is a Dyck path; that rearrangement is its **shape**.

The **Tamari order** on Dyck paths of height `n` is generated by: whenever
`a_{i-1} < a_i`, let `(a_i, ..., a_k)` be the **primitive** subsequence starting
at `i` -- the longest run with `a_j - a_i < j - i` for `i < j <= k` -- and set
`alpha <= beta` for the `beta` obtained by decreasing `a_i, ..., a_k` by one. Its
maximum is `(0, ..., 0)` and its minimum is `(0, 1, ..., n-1)`. The lattice is
**not graded**, so `d(alpha, beta)`, the length of the **longest** chain from
`alpha` up to `beta`, is a genuine longest-path quantity.

An object is a pair `(f, alpha)` with `alpha <= beta(f)`, encoded as the string
`f + "|" + alpha` with comma-separated values. For example the `n = 2` object
whose parking function is `(1, 0)` and whose `alpha` is the Tamari minimum is

```text
1,0|0,1
```

The Python submission receives a `TamariParkingPair` object with:

- `pair.n`, `pair.size` (`= n`)
- `pair.parking_function` (`f`), `pair.alpha`, `pair.beta` (the shape), `pair.minimum`
- `pair.area()` (`= area(beta(f))`, the chain length from the Tamari minimum)
- `pair.chain()`, `pair.dinv()`

`pair.chain()` is a search in the Tamari interval; it is a closed form at the two
extremes (`0` at the shape, `area(beta)` at the minimum) and cheap for the public
sizes, but expensive in between for large objects. The resource gate deliberately
includes large pairs whose `alpha` is at neither extreme, so a submission that
calls `pair.chain()` on them will exceed the time limit.

## Public Statistics

Both public statistics are implemented in `known_statistics.py`:

```text
chain(f, alpha) = d(alpha, beta(f)),    the longest Tamari chain length;
dinv(f)         = #{ i < j : c_i = c_j and a_i < a_j,
                             or c_i - c_j = 1 and a_i > a_j },
```

where `(a_i, b_i)` is the lexicographic rearrangement of `(i, f_i)` ordered first
by value and `c_i = i - b_i`.

## Public Data

`data/polynomials.json` contains the target `H_n(q1, q2, q3)` for `1 <= n <= 5`;
each term is `[chain_exponent, dinv_exponent, partner_exponent, coefficient]` and
`variables` is `["q1", "q2", "q3"]`. The range stops at `n = 5` because that is
where the published trigraded Frobenius characteristics stop -- there is no known
formula for `Harm_n`, so the target is not something a generator can extend.

`data/q_equals_1.json` contains the `q1 = q2 = 1` specialization, the required
one-variable distribution of the unknown third statistic (a necessary, not
sufficient, condition). Each term is `[partner_exponent, coefficient]`.

`data/instances.json` lists the public objects (`n <= 4`) with their `chain` and
`dinv` values. It does not contain the target statistic.

**`data/instances.json` is a sample, not the scored set.** It lists 437 objects over 4 of the 5 scored fibers, while scoring runs over all 7,349 objects of the range in `data/polynomials.json`. Its `instances_max_*` field bounds that sample only. Enumerate the full scored range with `qtbench.combinatorics` before trusting a proposal.

## Submission

Submit a short, self-contained Python file defining:

```python
def statistic(pair) -> int:
    ...
```

The return value must be a nonnegative integer. See `docs/checker.md` for the
admission checks.

To score it:

```bash
uv run --frozen python scripts/evaluate/evaluate_scored_submission.py tamari path/to/submission.py
```

## Scoring

After the capability and source-economy screens, the evaluator enumerates each
public size once. From the same submitted values, it checks the explicit
`q1 = q2 = 1` marginal and every `q1,q2,q3` coefficient. Only a complete match
proceeds to fresh-namespace shuffled replay and large
adversarial pairs under CPU and memory limits. A mismatch stops the evaluation,
and passing the marginal alone is insufficient. Every stage must pass, though a
pass is necessary but not sufficient for a genuine statistic (see
`docs/checker.md`).
